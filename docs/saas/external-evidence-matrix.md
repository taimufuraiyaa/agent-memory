# P0-P12 External Evidence Matrix

Status captured on 2026-08-09. This matrix is the handoff boundary between the
implemented self-managed product and claims that require a real staging or
production deployment, approved external integration, elapsed observation
window, independent reviewer, or accountable business owner. Repository tests
are supporting evidence only; they cannot replace the externally retained
artifacts listed here.

The current workspace has no release image digests, staging kubeconfig,
self-managed staging/production inventory, or reachable staging cluster. Every
row below remains open until its evidence is stored in the external immutable
evidence system and the applicable signed release decision references its
SHA-256 digest.

The machine-readable source for these 57 control IDs is
[`api/evidence/v1/external-control-catalog.json`](../../api/evidence/v1/external-control-catalog.json).
Use the [signed external-evidence index runbook](external-evidence-index.md) to
assemble and verify dossiers. A complete local fixture proves the verifier, not
the controls in this matrix.

## Evidence rules

- Use content-free identifiers in application tables and release artifacts.
- Store reports, contracts, screenshots, logs, infrastructure exports, and
  external-integration exports outside the application database.
- Record artifact SHA-256, accountable owner, observation interval, environment,
  release ID, and immutable image digests.
- Sign owner decisions using the workflow in
  [Signed Release Approvals](release-approvals.md).
- Verify trust and approval JSON from the exact validated opened-file bytes and
  require one unchanged approval-directory membership/file-identity snapshot;
  concurrent export changes fail closed and must be retried.
- Make the path-based canonical verifier own catalog, index, trust, approval,
  signature, and dossier verification as one logical decision. Revalidate all
  metadata paths and the approval snapshot after dossier hashing, and derive
  downstream source digests from that same operation.
- Re-stat every opened evidence descriptor after decoding and revalidate its
  path with non-following `Lstat`; regular-file identity, size, and modification
  time must remain unchanged. A symlink to the original inode is still rejected.
- Publish normalized receipts through one captured non-symlink parent-directory
  root; temporary creation, create-only final linking, cleanup, and directory
  sync remain descriptor-relative and parent replacement fails closed.
- Require the production verifier's compiled semantic digest of the exact
  ordered 57-control catalog; a truncated, reordered, or semantically changed
  catalog must fail before evidence readiness is evaluated.
- Open one validated artifact-root descriptor for the complete dossier pass;
  keep all dossier opens root-relative, recheck non-symlink intermediate
  directories, snapshot every approval-eligible indexed dossier before the
  first hash, bind each hash to that captured file, and repeat the complete set
  after the last hash so an earlier dossier cannot change during a later pass;
  retain that root through final metadata/approval checks, repeat the dossier
  set once more, and fail if any intermediate directory or the public root
  identity changes.
- A local emulator, mocked rollback, fixture approval, or checklist edit never
  proves a staging, production, legal, staffing, or independent-review claim.
