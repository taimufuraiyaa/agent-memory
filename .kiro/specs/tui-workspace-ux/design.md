# Terminal Workspace UX Design

## Multi-project discovery follow-up

The user's clarification that Agent Memory serves all projects exposes a discovery gap: a correctly empty selected project looks disconnected, and generic Workspaces records hide which projects contain knowledge. Extend the launch picker with asynchronous count summaries and give the existing Workspaces destination a dedicated project presentation. Keep registry names visible immediately, preserve the highlighted identity when counts arrive, and let selection/cancellation proceed without waiting for count completion. Within a project, show its count near the scope label and offer all-project navigation from empty Memories/Search. This is a project overview and switcher; retrieval and writes keep an explicit project scope.

Reuse the existing project-list contract with an additive count_status field. A ready count is scoped by the registered project name; unavailable metadata must never render as a known zero. Older remote APIs lacking count_status remain compatible when they return a valid memory_count. Counts read only existing regular database files through SQLite read-only/query-only connections, without store initialization or schema migration. Use the existing workspace index for count queries, bound each query to a short deadline and the whole scan to five seconds, and propagate caller cancellation. Missing, invalid, busy or old-schema files remain listed with count unavailable. Count failures do not hide the project or prevent choosing it; opening its runtime produces the normal authoritative error.

Local CLI/TUI default database resolution must honor a registered path, with an explicit --db taking precedence and unregistered legacy workspaces retaining their usual default path. Invalid registry data is reported rather than silently creating a second empty store. Remote operations retain their remote routing and bypass local registry path resolution. The embedded terminal service reads the normal registry directory rather than assuming it lives beside an explicitly chosen database. Switching still uses the established backend selector and a new model generation, resetting project-local results/history and rejecting delayed callbacks from the old project.

Alternatives include inferring a populated project, merging all memories by default, or opening every store through the migration-capable runtime. These would respectively hide scope, change retrieval/authorization semantics, or mutate databases during discovery. Read-only counts plus deliberate switching make all registered projects discoverable with a small additive metadata contract. A live global search would require a separate federated retrieval contract, including ranking, authorization, provenance and partial failures, and is outside this discovery change.

Risks include missing databases appearing empty, counts from unrelated rows in a shared file, nonstandard registered locations, delayed loads changing picker selection, SQL URI special characters, and terminals clipping recovery controls. Tests cover these cases with real SQLite fixtures and keyboard/render checks. Counts are point-in-time summaries, not cached canonical state; refresh reloads them. Sequential bounded metadata reads avoid an unbounded connection fan-out. No schema, model service, daemon lifecycle or account capability changes. Roll out read-only summaries, picker/Workspaces/empty presentation, and path parity in tested increments, then run the terminal release gate and atomically refresh both installed binaries. Rollback changes code/executables only.

## Architecture and interaction model

The existing Bubble Tea model and Go service adapters remain authoritative. A presentation/navigation layer centralizes daily destinations and contextual actions, rendering a shared shell around core and domain screens. A persistent rail appears when the terminal can accommodate a usable content pane; compact layouts expose the same grouped navigation through Ctrl-K. Ctrl-B focuses navigation, arrows select, Enter activates and Esc returns to content. Tab/Shift-Tab cycle daily destinations outside editing; input widgets retain Tab for field movement.

Destination and action palettes reuse the existing inventory, with an independent bounded query and filtered cursor. Esc closes the overlay and restores the current record/form scope. Action selection uses the current record only when its domain matches, preventing an unrelated selected ID from being reused. Busy/retired workspace guards run before navigation. Workspace switching retains the existing unique generation boundary and resets workspace-local display state.

Wide record screens split list and preview. Enter still fetches a complete note through the existing detail endpoint; summary previews never claim to contain a full document. Notes have active/trash filtering and Sources show imported source records. Filtering is local to the bounded loaded page, with that limit disclosed. Selection is resolved through filtered records rather than assuming an underlying array index. Detail scrolling and list selection remain independent. After a successful note action, the returned note is readable immediately and the local list is reconciled from that authoritative returned record; a refresh remains available.

## Daily workflow presentation

Home uses counts, recent knowledge and direct next actions. Ask has a minimal question composer with safe retrieval defaults and an optional advanced section. The latest question/result stays in workspace-local model state across destination changes; durable history continues through the existing private bounded history backend. Reading mode scrolls results; editing mode clearly identifies the question field and sending/review keys. Empty grounded retrieval offers explicit Search/Sources recovery. The renderer uses the actual recall-preview fields, including full included memories and weak-memory results, and never invents source evidence or an LLM answer.

Typed record documents order human content first, followed by provenance/state and useful timestamps. A detail inspector retains full advanced metadata, with recursive secret redaction. Generic advanced domains retain a readable document fallback; domain operations remain in the searchable action palette even when they are not daily navigation items. Graph/status and rights/policy evidence retain their native semantics.

## Form contract and editing

Progressive form disclosure is a view over the unchanged action/field contract, not a second request schema. Primary fields are explicit by common action; existing valid defaults and selected identity/revision values stay in the form and are submitted. Advanced fields can be revealed with Ctrl-O. Required fields without a safe default remain reachable. A single active-field caret supports rune-aware insertion/movement/deletion. Choice fields use left/right cycling; multiline values retain paste, Ctrl-J and external editor support. Field and response bounds remain unchanged.

Note title/body composition is explicit: the title controls the first Markdown heading, preserving the remaining body. Existing heading text is replaced as a heading, while body text without a heading is retained beneath the title. New paths use a title slug and a per-form identity seed so cancellation or retries cannot create a different target path; an explicitly entered path is preserved. The assembled body is size checked. Review presents the actual prepared request, with secrets masked, before a backend mutation. Note/client optimistic revision and stable graph/orchestration idempotency values remain intact.

## Alternatives and trade-offs

Keeping generic API documents as every primary view is inexpensive but forces users to learn transport structure. Recreating every browser widget would overcomplicate the terminal and duplicate domain logic. The chosen approach gives daily workflows dedicated presentation and keeps a complete advanced inventory. A rail trades some horizontal space for discoverability; responsive hiding protects the minimum viewport. Loading full note bodies only on selection avoids fetching every document. Latest-result context plus existing private history avoids introducing a conversation service or changing stored data.

## Failure modes, boundaries and scaling

Filtered selection, delayed detail loading, palette cancellation, stale editor callbacks, long documents, resized terminals and invalid backend documents are regression targets. Every string is sanitized before terminal rendering; forms/inspectors redact nested credentials. Mutations block duplicate sends and global navigation until completion. Load/detail/action generations remain attached to the same destination intent. Note mutation reconciliation uses returned server data and does not claim a failed indexing state is ready.

Layouts calculate available rows before rendering so errors, notices, field hints and footer remain visible. Lists and palettes draw only a viewport slice. Matching is linear over the small bounded catalog/loaded records, with input capped. Document wrapping is bounded by the existing result limits; no new network calls occur during rendering. No DB schema, trust classification, retention setting, daemon lifecycle, dependency or remote service is added.

## OpenCode follow-up: spatial focus and visual hierarchy

The official OpenCode reference uses restrained header/output blocks and an accent-edged bottom prompt, with Ctrl-P command discovery and four-direction text movement. Adapt these patterns to Agent Memory with a right-side workspace/context panel, a centered Home action card, readable Ask transcript and a consistently framed composer. On compact terminals the context panel becomes the existing destination dialog. All labels represent actual workspace/retrieval state; no model answer, token usage or service readiness is invented.

Use existing selected-record and detail state as the list/read focus boundary, plus the existing navigation-focus flag for the right panel. This avoids a second competing focus state. Spatial transitions are list → read → workspace to the right and workspace → content or read → list to the left. A detail request marks read intent before dispatch; leaving it invalidates the generation so late results cannot reopen reading. Home retains a small action cursor. Navigation cursor movement is selection, while right/Enter explicitly activates it. A hidden panel is reached through the destination dialog. Resizing never traps focus in invisible navigation.

Input takes precedence over pane movement. Multiline up/down preserve a desired rune column across logical text lines; shorter lines clamp the actual caret without changing that preferred column. Any horizontal movement, insertion/deletion, editor replacement or field change resets the column preference. Single-line/choice up/down keep field navigation; Tab/Shift-Tab and Ctrl-Up/Down work for all fields. Unicode editing must not split rune bytes. Wrapped rendering remains caret-aware, while logical line motion deliberately avoids coupling the stored draft to viewport width.

Alternatives: keeping the left rail retains familiar placement but differs from the requested context-panel direction; directional destination cycling alone offers four keys but does not navigate visible panes; a generic focus graph adds unnecessary state for this bounded layout. Existing detail state plus explicit spatial helpers keeps the behavior understandable and preserves Enter/Esc compatibility. Quiet neutral backgrounds must keep focused selections legible without color using markers and focus labels. Bounded centered dialogs and cards must reserve footer rows before calculating padding, especially at 60x16. Right/left navigation never dispatches writes, and mutation review retains y-only confirmation.

Verification adds arrow-only list/read/panel journeys, stale-detail cancellation, resizing while navigation is focused, filtered record identity, page scrolling, Unicode vertical caret and draft retention. Real PTY checks use actual arrow escape sequences for Home, memories and note reading, verify changed focus markers, then complete the established revision-2 note workflow. Refresh installed binaries only after focused/full/vet/build and the expanded PTY gates pass.
