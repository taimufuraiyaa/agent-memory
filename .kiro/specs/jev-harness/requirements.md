# Jev Harness Requirements

## Goal and scope

Agent Memory owns a local coding-agent harness, not merely memory selection. A registered MCP client can start, inspect, steer, cancel, and retrieve the result of a bounded run against a registered workspace. The Go service owns context assembly, model and tool routing, policy, execution, and state. The existing Node stdio MCP server remains a transport adapter. No hosted service is introduced.

This repository specification is the implementation authority. TypeSafe's published System One OpenAPI (2026-10-04) defines a bearer-authenticated `POST /v1/systemone` typed-decision endpoint and `GET /v1/models` live discovery. A real TypeSafe adapter may be built against that contract; a different OpenRouter account/key is not assumed. Provider egress remains separately opt-in and the rest of the harness still requires its authority/runtime gates.

## Requirements

1. **Client workflow.** An opt-in, separately authenticated client can discover effective capabilities, start a run, page status/events, continue with clarification, inspect bounded artifacts, and cancel. Start returns promptly. Existing default and expanded MCP tools remain unchanged. A profile ID, loopback address, or caller-supplied principal is not proof of authority.
2. **Run lifecycle.** Versioned states include queued, running, needs-attention, cancelling, completed, partial, failed, and cancelled. Mutations require idempotency and expected generation. A restart recovers a valid checkpoint. Cancellation propagates to all active providers. Budgets cap turns, time, tool calls, output, spend, and recursion.
3. **Provider-neutral core.** Versioned contracts define identities, manifests, live access, bounded requests, typed outcomes, and cancellation for decision, model, and tool providers. Registration rejects duplicates. A missing or unsupported provider is an explicit unavailable state. Two materially different fake providers prove shared workflow independence.
4. **Context.** Only authorized memory, solution, repository, instruction, and run evidence reaches an eligible model or Jev provider. Chunks retain source, revision, sensitivity, trust, token estimate, and lifecycle. Visibility is hide/short/long/full; active instructions remain pinned. Prompt and schema budgets are coordinated. Untrusted repository text is evidence, never policy.
5. **Jev decisions.** Typed, bounded, versioned Jev recommendations cover visibility, model, tool, cache strategy where measurable, command risk, file sensitivity, and subgoal deduplication. Malformed, slow, stale, denied, and unavailable responses have explicit safe fallbacks or required-dependency failures. Jev never grants access or execution authority.
6. **Model routing.** Live model capability, sensitivity eligibility, token/cost metrics, latency, and prompt-cache evidence govern selection. Retrieval query cache is not confused with model prompt cache. One real coding-capable model plus a different fake family must pass conformance.
7. **Tools and approval.** Tiered search, read, test, edit, and Git capabilities validate exact arguments and project-root confinement. Mutations are prepared, then deterministic allow/ask/deny policy decides. An ask waits for trusted local UI/CLI approval bound to run, generation, action digest, expiry, and file revisions. MCP continuation cannot approve. Stale approval or symlink escape fails closed.
8. **Workers.** Read-only workers can share an authorized snapshot. Subgoals deduplicate. Mutating workers use locks or isolated branches and revision checks. All inherit parent ceilings and cancellation.
9. **Data and privacy.** Transient run chunks have bounded retention separate from durable memory and solution episodes. Raw hidden reasoning, secrets, and unbounded provider/tool output are never durable. Status/events and errors are content-minimized; cross-client run existence is not disclosed.
10. **Compatibility and proof.** Existing local API, CLI, dashboard, memory, solution, skill, and MCP behavior must remain compatible. Fake and real provider conformance, auth/isolation, stale-state, restart, cancellation, adversarial tool, and MCP-to-Go tests are release gates. A live coding task demonstrates the full flow.
11. **Local Jev credential setup.** The local TUI lets a user set, replace, and remove a Jev access token without echoing it, printing it in errors, or storing it in workspace config, memory, or the database. A private user-level credential store reports only configured/not-configured status. Token presence does not imply Jev connectivity or harness readiness. Real Jev authentication and token validation remain gated on the verified Jev protocol.
12. **Claude Code listen bridge.** A user-invocable `/am listen` control in a connected Claude Code project can opt in or out of per-prompt Agent Memory context. The registered workspace root and submitted cwd must match; unrelated Claude hooks, MCP servers and skills survive connect/disconnect. Disabled or unavailable listening adds no context and never blocks a prompt. Output is bounded, content-minimized and truthful: it may supply authorized Agent Memory recall but must not claim Jev skill/model choices, switch Claude's model, or send prompts to Jev before those capabilities are implemented and separately enabled.
13. **Optional Jev onboarding during setup.** After successful interactive install, and after successful interactive upgrade when no Jev token is configured, ask whether to set a Jev access token. Approval must be explicit; entry must be masked and use the existing private user-level credential store. Skipping or cancelling leaves the token unchanged and setup succeeds. Existing tokens are never replaced by upgrade. Non-interactive, JSON, dry-run, and hooks-only paths must not prompt or alter credentials. No API validation or Jev readiness claim follows storage.
14. **Real Jev decision slice for Claude listen.** A separate explicit user opt-in permits bounded, redacted prompt text and only local project skill names/descriptions to leave the machine for TypeSafe Jev. A bearer-authenticated TypeSafe adapter probes the live model list and sends typed choice questions for task complexity and optional skill suggestion. Candidate IDs, probability map, confidence, response size, deadline, model identity, and scope are validated before any advisory context reaches Claude. Missing/invalid credentials, malformed/slow/denied responses, or low confidence fall back to local recall without Jev claims. Status reports Jev readiness only when opt-in, credential, and live probe all succeed. No model switch, skill auto-load, tool grant, or broader harness authority is implied.

15. **Unified listen control.** `/am listen` remains the single user-facing control for the prompt listener. Plain `/am listen` enables local recall only; `/am listen all` explicitly opts into both local recall and Jev advisory after credential and live-access validation. `/am listen status` reports both; `/am listen off` disables both. A failed Jev enable attempt must not silently enable remote egress or change an existing listener state. Legacy `/am jev on|off` forms may remain as compatibility aliases.

16. **Host-scoped model choice.** A user-owned versioned catalog explicitly allowlists candidate model IDs and bounded descriptions for `claude` and `chatgpt` hosts; there are no implicit account entitlements or hard-coded latest IDs. Jev sees only eligible candidates for the requested host and a redacted bounded task. The chosen ID must match the allowlist and pass confidence checks before a recommendation is returned. A missing/unsafe catalog, fewer than two candidates, absent consent, or provider failure returns no model choice. Claude's prompt hook may show a recommendation but must not claim to switch its active model. ChatGPT app/API execution is a separate host capability; the shared selector does not imply either is connected.

17. **Separate ChatGPT app and OpenAI API routes.** Preserve `chatgpt` as an app-facing recommendation catalog and add a distinct `openai_api` catalog so app entitlements are never mistaken for API availability. An explicitly invoked, bounded local API command may select only an `openai_api` candidate through Jev, verify that the account can retrieve the selected model, and create one text-only OpenAI Responses request using a separately supplied API key. No task is sent to OpenAI or TypeSafe without explicit per-call approval; no tool execution, file mutation, existing ChatGPT conversation switch, or ongoing autonomous run is implied. The ChatGPT app path remains recommendation-only until a supported host control is available; the user can apply it in the model picker.

18. **Claude subagent model routing.** With Jev listening explicitly enabled for the registered project, a managed `PreToolUse` hook matching Claude Code's `Agent` tool may send only a bounded, redacted subtask prompt and Claude-host model candidates to Jev. A validated choice replaces only the Agent input's `model` field and preserves every other argument and Claude Code's own permission checks. Missing catalog, unavailable or uncertain Jev, wrong root, unsupported input, and timeout leave the original Agent call unchanged. The hook must not approve tools, switch the main session, route non-Agent tools, or claim the requested model was used without host confirmation. Turning Jev off stops subagent routing.

## Explicit exclusions

The first contract slice does not call a real Jev endpoint, expose runnable MCP harness tools, execute shell commands, or claim full-harness completion. Those require the later authority, runtime, and provider gates below.
